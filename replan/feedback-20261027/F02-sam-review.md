## 결론
고정 ROOT+14개 구매 노드·5가지, 필수 선행선, 선택과 명시적 구매 분리, 비색상 상태, 무료 투자 토글, 툴팁/고정 상세, 키보드 탐색, 작은 화면 목록 대체는 F06의 최소 구현으로 기술적으로 가능하다고 조건부 수용한다. 팬/줌·맞춤 아트·세이브·새 UI 프레임워크는 필요하지 않다. 다만 현재 UI에 배치만 바꾸는 경미한 작업은 아니다. 기존 사이드바를 전체화면 상점으로 바꾸고 거래/입력/선택 상태를 연결하는 작업이다.

수용 조건은 아래의 지도 재배치, 작은 화면 필터/포커스 보완, F04/F05 완료판과의 통합 및 실제 격리 UI 시험이다. 이번 문서 검토를 위해 F04 차단을 해제하거나 우회할 필요는 없다. F06 구현 착수는 기존 선행조건에 계속 의존한다. 검토 완료는 F02/F06 구현 완료·대표의 가격/비주얼 개별 채택이 아니다.

## 실제 확인 근거와 한계
- F02 본문 전체와 두 SVG의 XML·좌표·문구를 직접 읽고 F01의 ID/선행/다음 전투 계약과 대조했다. 두 SVG는 정적 설계도다. 이번에 브라우저 렌더링·픽셀 충돌 검사·Unity UI 실행은 하지 않았다.
- 내부 정본 Assets/MGAME/Runtime/ElementalDemo.cs를 읽었다. UI Toolkit의 UIDocument/VisualElement/Label/Button/ScrollView를 이미 사용한다(5, 25~66행). 기존 UI 기술을 재사용할 근거가 있다. Canvas/uGUI로 전환해야 한다는 근거는 없다. F02의 'Unity Canvas 실측'은 현 구현에서는 UI Toolkit 패널의 실제 해상도·스케일 실측으로 구체화하면 된다.
- 같은 파일 52~62행은 폭340의 사이드바와 12개 카드, 클릭 즉시 Buy 호출이다. 19~20행의 본문/버튼 기본값과 58~59행의 카드 글자는 F02의 글자·클릭영역 기준과 다르다. 기존 스타일 재사용만으로 F02 크기 기준을 만족한다고 볼 수 없다.
- 78~81, 91~116행에서 매 프레임 Refresh가 실행되고, 95행에는 과거 구매개수 해금 안내, 99~100행에는 12개 구매와 3개 투자 토글 갱신이 있다. 전체화면 노드나 상세를 매 프레임 재생성하지 말고 기존 요소를 유지하며 거래/선택/모드 변경 때 상점 표시만 갱신할 것을 권고한다. 실제 병목이나 프레임 저하는 측정하지 않았다.
- DemoModel.cs 24~65행의 기존 12개 가격/Owned 배열, 동기 거래, 투자 소유/NextInvest 분리, 구매개수 해금과 73~94행의 다음 전투 재생성을 읽었다. 현재 코드가 이미 S01/S02를 지원한다는 뜻은 아니다. 명시 ID 대응과 구매개수 해금 제거는 F06의 필수 통합 비용이다.
- F04.md는 실행 정책 차단·구현 미완료를 기록한다. 내부 정본 읽기는 가능했지만 승인 격리 복사본의 최신 일치 여부·실행 바이너리 동일성은 이번에 확인하지 않았다. F04/F05 변경 후 최신 코드를 다시 확인해야 한다.
- 레이아웃 산술 보조용 python -c 호출은 무인 승인 정책으로 BLOCKED됐다. 계산 결과나 자동 검사 통과 수치를 만들지 않았으며 다른 실행기로 우회하지 않았다. 아래 레이아웃 지적은 읽은 원문 좌표/규칙의 비교이며 렌더링 결과가 아니다.

## 최소 구현안과 상대 비용
아래 비용은 설계상 상대 판단이며 실측·확정 견적·납기 약속이 아니다. 기존 UI Toolkit과 단일 로컬 모델을 유지하고 새 에셋/저장/컨트롤러 지원이 없다는 가정이다.

## Mia 보완 요청 — 설계의 핵심을 바꾸지 않는 세부
1. 넓은 지도는 1440×900 SVG 좌표를 1280×720에 그대로 복사하거나 전체 축소하면 안 된다. 상세 고정 폭을 제외한 트리 가용영역과 높이가 달라진다. SVG의 오른쪽 투자 카드가 트리 경계에 닿고, 하단 카드/추천문도 하단 쪽에 있으므로 1280×720 전용 가지별 좌표 보정이 필요하다. 최소 카드/본문 크기를 유지하는 고정 레이아웃 프리셋을 우선하고 선 교차 회피 자동 알고리즘은 만들지 않는다. 맞지 않으면 Mia와 가지 배치를 조정한다. 지도 최소 지원 기준을 임의로 올리지는 않는다.
2. 960×540는 목록/상세 분리와 ROOT/필터의 고정 영역을 함께 산정해야 한다. SVG에서 ROOT는 y72~120, 필터는 y132~176에 있다. 본문의 '상단72/하단64를 제외한 영역을 55/45로 분할'을 그대로 적용하면 ROOT/필터를 위한 추가 세로 공간을 누락하기 쉽다. 고정 헤더 아래 ROOT/필터, 그 아래 남은 영역에 목록/상세 스크롤이라는 순서를 명시할 것을 요청한다.
3. 640×480 단일열은 같은 5개 필터를 SVG 폭으로 유지할 수 없다. 필터는 텍스트가 읽히는 줄바꿈 배치 또는 가로 스크롤을 Mia가 선택하고, 키보드로 숨은 필터에 접근 가능해야 한다. '목록으로'는 상세에서 항상 접근 가능하게 두고 무료 시작/가격/CTA는 본문 긴 문구에 밀리지 않게 한다. 목록 위치는 가지별로 보존하는 단순 상태면 충분하다.
4. 현재 Tab 명세에는 가지 헤더/필터와 '목록으로'의 순서가 빠져 있다. 작은 화면에서 전체 노드 고정 순서를 유지하려 자동 필터 전환하면 사용자가 고른 필터가 매번 바뀔 수 있다. 권고: 넓은 지도는 기재된 전체 순서, 목록은 ROOT→가지 필터→현재 가지의 노드→상세 행동→무료 시작, 단일열 상세는 목록 복귀→상세 행동→무료 시작. 선행 보기는 해당 가지를 열고 노드에 포커스, 필터 수동 변경은 해당 가지의 기존 선택 또는 첫 노드로 이동. 원래 선택 보존과 '숨은 선택 자동 노출'을 모든 필터 클릭에 적용해 필터 전환을 즉시 되돌리지 않도록 예외를 합의해야 한다. 이는 Sam 제안이며 Mia 수용 전 확정 UX 변경이 아니다.
5. 모드 전환/거래 갱신 때문에 UI 트리를 재구성하며 포커스·누른 키를 잃지 않게 한다. 노드 Enter/Space는 선택, CTA에서만 구매, 비활성 CTA는 Tab 제외라는 F02 의도는 유지한다. 가지 헤더도 키보드로 이동시킬 경우 focusable 및 역할/복귀 규칙을 정한다.

위 보완은 F02 원문을 임의 수정하지 않고 응답으로 전달한다. 지도와 기존 독립 구매 규칙 사이에 새 핵심 충돌은 발견하지 않았다. 필터와 포커스는 구현 전 Mia가 수용/수정 응답할 세부이며, 문서 리뷰 자체의 외부 실행 차단 사유는 아니다.

## 더 싼 대안과 상신 조건
- 권고 기본안: 넓은 화면만 고정 지도, 작은 화면은 동일 데이터 목록과 동일 상세를 재사용한다. 별도 UI 프레임워크·모드별 거래 코드·사용자 배치 편집기 없이 목적을 달성한다.
- 선택적 150ms 테두리/짧은 음은 첫 최소판에서 생략 가능하다. 체크/잔액/상세 결과로 구매 성공은 유지한다. 이는 F02의 선택 요소를 줄이는 것이며 필수 접근성 정보를 없애는 대안이 아니다.
- 목록 전용을 모든 화면에 쓰면 지도/연결선 비용은 줄지만 '전체화면 중앙 시작 트리' 의도를 약화시킨다. 자동 채택하지 않고, 일정 압박이 실제 확인될 때만 Mia와 Sophie를 통해 대표에게 대안으로 상신한다.
- 팬/줌, 자동 레이아웃, 맞춤 아트, 새 저장, 별도 UI 시스템 전환, 장기100개 대응은 범위 밖이다. 이를 요구하거나 기본 글자/클릭영역을 지키기 위해 기존 최소판을 크게 재설계해야 하면 작업 범위·추가 예상량·잃는 UX를 먼저 구체 보고한다.
- 현재는 큰 비용 변경이 발생했다는 실측 근거가 없다. F04 정책 차단을 비용 증가나 새 승인 필요로 바꿔 말하지 않는다. 재개 시 실제 추가 작업이 커지면 '고정 지도 유지와 배치 보정' 대 '목록 전용 축소'를 대표의 구체 선택지로 올리고 임의 축소하지 않는다.

## F06 검증 인계 — 아직 실행하지 않음
- F04/F05 완료판과 승인 격리 위치를 확인한 뒤 기능 모델 시험과 실제 UI 시험을 구분한다. F02의 필수 시나리오 1~9를 누락 없이 실행한다.
- 모델: ROOT 구매 거절, S01/S02 선행, 같은 상점 연속 구매, U06 없이 U07/U09 없이 U08, 기존 구매개수 지급 제거, 중복/부정ID/전투중 구매 거절, 실패 시 무변경, 무료 투자 무차감과 다음 전투 스냅샷, 종별 최대1 재생성을 확인한다. UI 표시만으로 거래 성공을 판정하지 않는다.
- UI: 1920×1080/1440×900/1280×720/960×540/640×480 및 모드 경계의 바로 전후, 긴 한국어·폰트 폴백, 필터/선행 보기/상세 복귀의 선택·스크롤·포커스 보존을 확인한다. 기준 치수는 OS 창 크기와 UI Toolkit 유효 패널 크기/스케일을 함께 기록한다.
- 모든 기본/보조 상태와 무채색·음소거, 잠금 노드 정보 접근, Enter/Space 노드 선택과 CTA 구매, Tab/역순/자동 스크롤을 확인한다. 툴팁은 가장자리와 지연 중 선택변경도 시험한다.
