## 1. 추천 한 줄과 범위

같은 커서 범위 지휘 아래, 정령은 공격 형태의 조합, 용은 소수 개체의 진화, 동물은 종 구성과 마릿수, 악마는 표식 연계, 언데드는 턴 안의 제한된 증식으로 성장시키는 안을 추천한다.

재미 가설은 “강해진 수치뿐 아니라 공격 장면과 다음 구매 이유가 달라지는가”이다. 다섯 시스템을 동시에 만들 이유가 확인된 것은 아니다. 가장 싼 검증은 동일한 적 배치 그림 위에 업그레이드 전후 공격 결과를 표시한 종이 카드 비교다. 실제 전투 감각·시각 만족은 이 문서로 입증할 수 없다.

이번 카드의 책임은 비교표·ID 규약·필드 계약·참조 예시다. 기본1+추가4종, 전용10업그레이드, 2빌드, 상세 트리는 P1-07~11의 기존 카드가 작성한다. 여기의 추가 소환수는 각 직업의 대표 후보 1종만 두며 전체 콘텐츠 수량 충족으로 보고하지 않는다. P1-05는 병행 작업으로 아직 확정 인용하지 않았고, 공통 전투 경계의 최종 상세는 05와 통합 점검해야 한다.

## 2. 공통 규칙 — 승인 사항과 설계 제안 분리

### 2.1 G1 고정 기준

1. 골드 드랍 시 즉시 자동 수집. 자동 수집 구매·바닥 골드 회수·수집 반경·수집률은 직업 능력이 아니다.
2. 소환수는 커서 공격 지정 범위 안 몬스터를 공격. 범위 확대 업그레이드 존재. 직업 특성이 범위 밖 자동 공격의 우회로가 되어서는 안 된다.
3. 초기 전투 길이 30초 고정. 시간 증가 업그레이드는 보류.
4. 성장·시각 만족 우선. 역할 변화형 군단이나 복잡한 보스 기믹을 필수로 강제하지 않는다. 단순 화력 측정 보스 허용.
5. 보스 입장·실패·재도전 비용/패널티 없음. 재도전 보스 HP 초기화. 무한 성장·환생 제외.
6. 소환수 무피격 원안 문맥 유지. HP 희생·방어·치유·아군 피격 시스템을 직업 차별화 명목으로 새로 넣지 않는다.

### 2.2 이 문서의 임시 공통 경계 제안

아래는 승인 사실이 아니며 P1-05/12/14에서 조정할 수 있다. 서로 다른 직업이 임의로 반대 규칙을 만들지 않도록 하는 비교용 기준이다.

- 공격 지정 반경(command_radius): 커서 중심의 대상 자격 영역. 공격 사거리(attack_range): 소환수에서 적까지의 도달 거리. 효과 반경(effect_radius): 적중 위치 주변 피해 영역. 세 값을 별도 필드로 둔다. 크기·좌표·상한은 05/14에서 정한다.
- 기본·광역·연쇄·표식 폭발·지속 피해 모두 피해 처리 시점의 지정 범위 안 살아 있는 적만 피해 대상으로 삼는다. 범위 밖 이탈 시 새 피해/표식 적용을 중단한다. 이미 발사한 투사체도 적중 시 자격 재확인하는 보수적 안. 직업별 예외 없음. 이는 투사체 낭비를 유발할 수 있으므로 05에서 이탈 처리 대안과 비교해야 한다.
- 지정 범위가 비거나 커서가 전장 밖이면 신규 공격·연계 발동을 하지 않는다. 전장 전체 대체 탐색 없음. 범위 밖에 있는 아군의 존재와 공격 대상의 범위 안 자격은 구분한다. 아군 이동·정렬 방식은 05/Sam 소관.
- 직업 선택은 한 런 동안 유지하고 직업 혼합·전투 중 개별 소환수 수동 스킬은 이번 후보에서 제외한다. 상점에서 구매하고 다음 전투부터 적용하는 안. 런 중 직업 변경/환불은 별도 미결정이다.
- 구매 레벨·영구 해금·영구 진화는 같은 런의 다음 턴에도 유지. 표식·시체 토큰·임시 소환수·발동 횟수는 전투 종료 때 초기화하는 제안이다. 보스 재도전도 동일한 시작 상태에서 시작해 실패 누적으로 강화되지 않게 한다.
- 영구 소환 수와 임시 소환 수 모두 유한 상한을 가진다. 시체/표식/연계는 골드를 직접 생성하지 않는다. 실측 없는 동시 개체 상한을 성능 보장으로 해석하지 않는다.

### 외형 교체인지 확인하는 반례 비교

모든 스킨·공격 색·명칭을 제거하고 같은 예산/적 배치/커서 경로를 준다는 비교 설계다. 결과는 예측이며 실측 아님.

- 정령 vs 용: 둘 다 광역이어도 정령은 서로 다른 공격 개체 추가, 용은 기존 주력 형태 변환/슬롯 교체. 모든 정령을 단일 대형 개체로 합치면 구분 소실.
- 동물 vs 네크로: 동물은 구매한 영구 무리가 턴 시작부터 존재, 네크로는 처치 토큰에 따라 턴 안에서 임시 증식. 언데드를 구매 마릿수만 늘리면 구분 소실.
- 동물 vs 악마: 동물은 종 보유 여부로 시작 시 보너스, 악마는 적별 표식과 소비 사건의 순서. 악마를 단순 동시 보유 버프로 바꾸면 구분 소실.
- 정령 vs 악마: 정령의 연쇄는 1회 공격의 대상 분포, 악마는 서로 다른 소환수가 같은 적의 상태를 연결. 악마 소비 효과를 임프 자체 폭발로 바꾸면 구분 약화.
- 용 vs 네크로: 용은 런 간 구매가 아닌 같은 런의 영구 진화 단계, 네크로는 턴 내부 임시 전력. 양쪽 모두 일반 공격력 증가만 남으면 차별화 실패.

다섯 직업 모두 어려운 조합을 필수로 만들 필요는 없다. 역할 변화는 선택 후보이며, 복잡한 기제의 설명·시각 비용이 성장 만족보다 크면 해당 직업 확장을 보류한다.

## 4. 공통 데이터 계약 v01 — 문서용 제안, 엔진 구조 지정 아님

### 4.1 ID 규약과 관리

- 직업: CLS_ELM, CLS_DRG, CLS_BST, CLS_DMN, CLS_NEC. 공통 적용 범위 값은 ALL이며 직업 ID로 생성하지 않는다.
- 소환수 정의: SUM_{직업코드}_{영문명}. 예: SUM_ELM_EMBER. 번역 표시명과 분리해 명칭 변경에도 ID 유지.
- 업그레이드: UPG_{직업코드 또는 COM}_{영문효과}. 진화 단계는 동일 소환수의 stage_id로 관리. 별도 공격 형태가 된다는 이유만으로 새 종 수량으로 세지 않는다.
- 효과: EFF_{영문효과}, 비용 정책: COST_{영문명}. 해금/선행 참조는 ID+필요 레벨로 표기하고 표시명으로 연결하지 않는다.
- ID는 대문자 영문·숫자·밑줄만 허용, 테이블 안 중복 금지, 삭제된 ID 재사용 금지. 이전 ID 변경 시 old_id→new_id 이전표 필수.
- 기획 틀 버전 schema_version=1. 콘텐츠 ID는 아래 예시를 예약하며 07~11은 같은 후보를 유지하면 재사용, 다른 후보면 새 ID 사용하고 변경표 남김. 공통 필드 변경은 12/14와 협의한다.

| effect_ids / trigger | Effect ID 배열 / basic_hit, death_event 등 발동 사건 |
| stage_id / evolution_steps | 초기 BASE / 단계명·효과 변화·진화 Upgrade 참조. 유한·순환 금지 |
| unlock_upgrade_id / slot_cost | starter/temporary는 null, unlock이면 Upgrade 참조 / 양의 정수 |
| persistence / visual_change | run 또는 turn / 실루엣·개체 수·탄도 변화, 색만으로 구분하지 않음 |
| scope / status / source_ref | 범위 구분 / proposed / 원문·후속 문서 참조 |

공격력·주기·거리·개체 상한을 이 카드가 확정하지 않는다. 수치 없는 기획 후보는 후속 밸런스 표에서 채워야 하며 null을 0으로 임의 대체하지 않는다.

### 4.4 Upgrade 레코드 — 원문 10항목+유형 보존

| 필드 | 정의·제약 |
|---|---|
| id / name | 고유 ID / 표시명 |
| category | game, monster, gold, summon 중 하나 |
| applies_to | ALL 또는 Class ID |
| effects | {effect_id, target_id, operation, value, unit, per_level_or_once} 배열. 추상적인 “더 강해짐”만 쓰지 않음 |
| max_level | 양의 유한 정수. 반복형도 상한 필요 |
| cost | {currency:gold, base, growth_rule, rounding, status}. base·증가율은 양수 가정 또는 null+이유 |
| unlock_condition | 런 시작 또는 조건식. 선행과 별개 진행 조건 없음도 명시 |
| prerequisites | [{upgrade_id, required_level}], 없으면 [] |
| visual_change | 화면에서 확인할 변화. 수치형은 크기/피드백 또는 변화 없음 명시 |
| type | repeat, unlock, evolve, synergy 중 하나 |
| scope / status / source_ref | 후보 범위 / 제안 여부 / 요구 추적 |

필수 10항목은 id·name·category·applies_to·effects·max_level·cost·unlock_condition·prerequisites·visual_change이며 type을 추가한다. unlock_condition과 prerequisites의 교집합을 만족해야 구매 가능하다. 비용과 효과 적용의 중복 실행 금지, max_level 도달 후 구매 불가. 수치 곱셈 순서는 12/14에서 일원화하며 직업별로 별도 복리식을 만들지 않는다.

### 4.5 Effect·전투 상태·원장 계약

- Effect: id, trigger, target_selector, operation, value/unit, stack_rule, cap, reset_scope, can_trigger_other_effects, reward_policy. 수동 HP 대가·골드 회수 조건은 없음.
- target_selector=cursor_eligible_only. 재귀 연계 기본 금지. 부가 피해 사건은 기본 공격 적중 사건을 다시 만들어 표식→폭발→표식 무한 고리를 만들지 않는다.
- 종 보유 보너스는 같은 종 여러 마리로 중복 활성화하지 않음. 같은 효과 ID는 한 번 적용하고 수준 상한으로 갱신한다.
- 시체 토큰은 corpse_token_count라는 턴 한정 상태, 바닥에 주워야 하는 골드/아이템이 아님. 몬스터 고유 death_event_id당 한 번 증가, 아군 임시 소환 소멸에서는 생성하지 않음.
- 골드 원장 최소 필드: battle_id, death_event_id, monster_id, gold_granted, grant_status. 몬스터 사망 보상은 한 번만 즉시 지급. 시체 소비·표식 소비는 별도 골드를 생성하지 않음. 보스 보상 유무/상자는 이 카드가 결정하지 않는다.
- 성장 비교 기록: 직업/구매 ID·순서, 시작·종료 소환 수, 커서 안 유효 대상 시간, 공격 형태 변화, 처치 수, 실제 지급 골드, 빈 범위 시간. 수집률·미수집 골드 손실은 측정 항목에서 제거.

## 7. 플레이 예시와 최소 검증 설계

### 7.1 같은 상황에서 다른 구매 이유 — 예상 사례

정사각형 필드에 뭉친 적 무리와 떨어진 적이 있고, 커서 안 몬스터만 공격 가능하다. 첫 전투는 기본 소환수 1마리. 처치 보상은 커서를 움직이지 않아도 즉시 잔액에 들어간다. 30초 후 상점에서 다음 전투의 변화를 고른다. 아래는 실제 플레이 기록이 아니다.

| 직업 | 첫 투자 예시 | 다음 전투에서 관찰할 차이 | 반대 구매의 이유 |
|---|---|---|---|
| 정령 | UPG_ELM_BLOOM | 불씨 적중이 뭉친 적에 폭발. 반경 밖은 피해 없음 | 흩어진 적이 문제면 UPG_ELM_SPARK 우선 |
| 용 | UPG_DRG_ADULT | 한 주력용의 공격이 부채꼴로 바뀜 | 단일 적/공격 공백이 문제라면 비룡 해금·배치 검토 |
| 동물 | UPG_BST_PACK | 다음 턴 시작부터 늑대가 더 많음 | 다른 종을 먼저 얻고 싶으면 UPG_BST_HAWK |
| 악마 | UPG_DMN_EXECUTOR | 임프 표식을 집행 악마가 지우며 추가 타격 | 약한 적에 표식이 보이기 전에 죽으면 임프 기본 화력 경로를 10에서 비교 |
| 네크로 | UPG_NEC_RAISE | 처치가 쌓인 뒤에만 임시 해골 추가, 다음 턴은 원래 수 | 단일 보스에서는 UPG_NEC_LICH 등 영구 전력 우선 |

직업마다 늘 승리하는 구매 순서를 주장하지 않는다. 특히 악마의 기본 화력 경로·동물 보너스는 상세 카드 대기이며, 예산·DPS 비교 없이 빌드 균형이 맞는다고 말할 수 없다.

### 7.2 가장 싼 검증 계획 — 미수행

1. James: 각 직업을 이름·색 없이 “구매 전/후 개체·공격 궤적” 카드로 제시. 같은 그림에서 다음 구매 두 개 중 하나를 고르게 하고 이유를 묻는다. 기제 설명을 읽어주는 조건과 설명 없는 조건을 구분한다.
