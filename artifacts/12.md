## 1. 추천 → 재미의 원리 → 핵심 위험 → 가장 싼 검증

추천: 같은 상점에서 숫자 화력·지휘 원·적 공급과, 소환수 추가·형태 진화를 직접 비교해 사는 유한 성장 구조.

원리: 적 무리 지정 → 자동 처치/즉시 골드 → 이번 구매가 바꿀 장면 확인 → 다음 30초에서 변화 관찰. 범위를 늘리면 지정 가능한 적이 늘고, 개화/계약/무리 확장/소생은 실제 공격 분포나 개체 구성이 달라진다. 모든 업그레이드를 행동 변화로 꾸밀 필요는 없지만 숫자 구매만 유일한 합리적 경로가 되면 실패다. 역할 퍼즐·시너지를 필수 재미로 강요하지 않는다.

위험: 수입·화력·공급 투자가 서로 곱해져 한 정답 순서를 만들 수 있다. 범위·광역 구매는 단일 보스에서 효율이 낮고 네크로 증식은 보스 생존 중 0이다. 해금 집합 충족과 HP1000 처치 가능성은 다르다. 유한 전체 구매 후에도 못 잡는 상태는 최종 GDD 전 해결해야 하는 결함이다.

싼 검증 계획(미수행): 동일 적 배치의 구매 전후 카드와 같은 예산의 두 구매 목록을 제시해 무엇이 달라지고 다음에 왜 살지 설명하게 한다. 숫자·이름·색을 가린 조건도 비교한다. 이해 검증은 재미·미적 만족의 입증이 아니다. 실제 반복 지루함·커서 피로·구매 기대는 별도 승인 후 플레이테스트해야 한다.

## 2. 불변 규칙·카탈로그 사용 계약

### 2.1 승인과 제안 구분

G1 승인: 드랍 즉시 기본 자동 수집, 현재 커서 지정 범위 안 적 공격, 지정 범위 확대 가능, 성장/시각 만족 우선·단순 화력 보스 허용, 초기 전투30초 고정·시간 증가 보류, 보스 입장/실패/재도전 비용·패널티0 및 재도전 HP 초기화, 무한/환생 제외.

원안 유지/세부 제안: 무피격·아군 HP/희생/치유 없음, 상점 직접 구매·잔액/구매 런 유지, 전투마다 위치·표적·표식·토큰·임시군 초기화. 05의 엄격한 비행 중 지정 이탈 즉시 무효·재진입 비복원·소비 쿨다운 비환불을 모든 직업에 적용한다. 광역/연쇄/표식 추가 피해도 현재 지정 자격과 형상 교집합만 허용한다. 사거리만 이탈한 비행은 유지한다. 종료는 [0,T), 정확히 T 피해/스폰/드랍0. 이는 대표가 투사체/동시 사건 세부까지 승인했다는 뜻이 아니다.

R_cmd=command_radius(커서 지정 반경), R_reach=attack_range(개체 사거리), R_fx=effect_radius(공격 형상). 별개 값이며 어떤 강화도 나머지를 자동 변경하지 않는다. 골드 수집 반경은 존재하지 않는다.

### 2.2 데이터와 구매

정본 문서 데이터: [12-catalog.json](12-catalog.json). 아래 부록 A는 같은 레코드를 전수 펼친 표다. 필수 10필드 id/name/category/applies_to/effects/max_level/cost/unlock_condition/prerequisites/visual_change 및 type/scope/status/source_ref를 행마다 갖는다. effects는 원문 효과 명세를 보존한 문자열이다. 엔진용 Effect 배열·실행 payload가 아니며 06의 구조화 효과 필드로의 구현 변환은 Sam 검토 이후 별도 사양화한다. schema_version=1.1-document로 용도 차이를 표시했다.

분류는 game/monster/gold/summon, 유형은 repeat/unlock/evolve/synergy. 유형은 행의 주효과 기준: NEC_THRIFT의 evolve는 소환수 외형 진화가 아니라 소생 규칙 전환이다. 해금은 새 기능/개체/출전 슬롯 획득, 반복은 유한 최대레벨까지의 수치/수량 구매, 시너지는 조건부 보너스다.

현재레벨 L=0부터 다음 구매 비용 C(L). one_shot=C0, linear=ceil(C0+step×L), exponential=ceil(C0×2^L). 전용 식을 무리하게 하나로 바꾸지 않고 동일 비용 객체로 정규화했다. 현재 모든 계수는 정수라 올림이 기존 정수 비용과 같으며, 이후 소수 가격을 넣으면 공통 ceil만 한 번 적용한다. 모든 최초 가격은 양수 가정, null=무료 변환 없음. max_level 이후 다음 비용은 구매불가이며 표시하지 않는다.

구매 가능 = 상점 상태 AND 해당 직업/공통 적용 AND 해금조건 AND 모든 선행 레벨 충족 AND L<max_level AND 잔액≥C(L). 단일 구매 의사확정당 비용1회/레벨1회, 동일 요청 재처리로 중복 차감 금지. 구매 원장에는 purchase_id/run_id/upgrade_id/old_level/new_level/cost/balance_before/after를 기록하는 요구다. 빠른 연속 클릭·화면 재진입도 가격/조건을 현재 상태로 재검사한다. 일괄구매/자동구매·전투 중 구매·무작위 선택지·새 통화·환불/재분배 기능은 넣지 않는다. 환불을 하지 않는 가정이므로 잘못된 광역 구매로 돌이킬 수 없는 막힘이 없는지 14/15 검사 필수다.

표의 범위는 후보 구분일 뿐 제작 약속 아님. 다른 직업 항목은 상점에 구매 가능으로 노출하지 않는다. 선택 직업 외 선행은 허용하지 않는다. 구매 효과는 다음 전투 구매 스냅샷에서 재계산하며 UI 열 때마다 복리 누적하지 않는다.

## 3. 공통 항목·비용 통합 근거

공통 5항목은 부록 A의 ALL 표를 따른다. 기존 예약 UPG_COM_COMMAND_RADIUS의 ID·최대3 제안을 유지, 시작150/레벨당+50/최대300/최초15·step15는 이번 가정이다. 05의 비교값250은 L2에서 재현된다. L=1000 필드에서 전장 전체 지정을 종착점으로 만들지 않는다.

UPG_COM_POWER는 10/20/30 가격, 피해 최대1.30배. UPG_COM_SUPPLY는 20/50으로 s1/s2 해금, UPG_COM_GOLD_YIELD는 20/40/60으로 최대1.75배, UPG_COM_REACH는 25/50으로 최대+40 사거리. 정확한 효과/한도는 부록과 JSON 레코드가 명시한다. 수입·시간을 검증한 값은 아니다.

정령 가격은 07의 null을 이번 양수 가정으로 대체했다. BLOOM20/SPARK25/TIDE25/STONE45/PRISM100, SPARK_ARC45/TIDE_WAVE35/STONE_MONOLITH60/PRISM_CROWN90, POWER10+10L/TEMPO20+20L/SPLASH20+20L, DUET35. 다른 직업은 08의 선형 step, 09/11의 base×(1+L), 10의 2^L 비용을 유지한다. 비용 후보가 서로 다르다는 사실은 통합 오류가 아니라 비교 입력이며, 직업 간 동등 성장 속도의 증거도 아니다. 가격 원천은 각 cost.provenance로 추적한다.

두 대안: A 모든 반복 가격을 즉시 동일식/동일폭으로 변경하면 비교가 단순하나 원문 빌드 예산을 한꺼번에 바꾼다. B 효과/가격 원천을 유지하고 비용 스키마/평가 의미만 통일한다. B 권고. 14/15의 같은 예산 분석 뒤 조정하고 변경표를 남긴다.

금화 강화는 시각보다 순수 숫자 항목이라 초기 최소 비교에서는 제외 권고, 카탈로그에서는 확장 후보로 보존한다. 기본 적 1G에 floor를 쓰므로 일부 레벨에서 효과0인 적이 생긴다. UI는 실제 적별 지급 정수를 보여야 하며 표시 배율만으로 모든 처치 수입이 늘었다고 설명하지 않는다. A 사망별 floor는 원장 단순하지만 죽은 레벨 위험, B 소수 지갑/누적 이월은 작은 보상도 늘리지만 새 경제 상태가 필요하다. A를 비교 기준으로 채택하고 죽은 레벨이 크면 강화폭/비용/항목 제거를 먼저 검토한다. B는 자동 도입하지 않는다.

## 4. 피해·주기·시너지의 통합 연산 [제안]

### 4.1 피해 순서

표기: B_stage는 진화의 set 피해를 적용한 원천값, F_flat은 원천값에 더하는 정액, A_class는 기준 피해 가산계수들의 합, M_evo는 명시된 진화 곱계수, F_post는 직업 마지막 정액. 공통 전 피해 D_class=(B_stage+F_flat)×(1+A_class)×M_evo+F_post. 최종 기본 피해 D_basic=D_class×(1+0.10×COM_POWER). 클래스별로 적용되지 않는 값은 0 또는1이다. 모든 반복은 기준값에서 산정하며 현재 피해에 누적 곱하지 않는다.

| 직업 | 원천/정액 | 직업 가산/곱 | 직업 마지막 정액 |
|---|---|---|---|
| ELM | 07 진화 set 피해(물결8 등). 불씨 POWER는 F_flat=2L, DUET 활성 불씨 F_flat+=3 | 추가 가산 없음, M_evo=1 | 0 |
| DRG | 종별 기준 피해 미정 그대로. ADULT는 분포 교체로 기본 피해 변화 없음 | WHELP POWER +0.10L, ANCIENT +0.30, MOON FOCUS +0.15L, 배치 DUET 해당 두 종 +0.10을 동일 A_class 안 합산 | 0 |
| BST | 종별 기준 피해 미정 그대로 | FANG 모든 종 +0.10L, 늑대 LEADER +0.20 및 CROWN +0.30, SKY_GROUND 활성 늑대/매 +0.10 합산 | 0 |
| DMN | 10의 종별 기본 피해 | POWER +0.20L 가산 뒤 IMP_CROWN/HOUND_FANG 해당 종 M_evo=1.5, 그 외1 | 0 |
| NEC | GUARD6/ARCH12/OSSUARY18 등 진화 set값 | BONE은 해골(임시 포함)만 A_class=0.25L. 리치/궁수/기사/거인에는 적용 안 함 | CONDUCT 활성 해골만 +2 |

NEC의 '마지막 +2'는 직업 내부의 마지막을 뜻하고 공통 POWER는 그 뒤 적용하는 안으로 일원화했다. A 공통을 마지막에 곱하면 모든 직업 보너스도 직관적으로 강화되나 시너지 곱효율이 커진다. B 공통을 별도 원천 가산으로 넣으면 폭증이 작지만 직업별 원천 예외가 생긴다. A 권고, 14/15에서 효율을 비교한다. CONDUCT와 DUET가 동시에 다른 직업에 활성화되는 혼합 런은 없다.

방어/치명타/속성저항 없음. 내부 피해·HP는 소수를 유지, 대상별 합산 후 사망 판정하며 매 타격 반올림/최소1 피해 보정 없음. 화면 피해 표시는 최대 소수1자리 반올림을 제안하되 실제 판정에는 재사용하지 않는다. 골드만 지급 단계에서 floor하여 정수 지갑을 사용한다. 최종 표시 방식은 Mia/Sam 검토 대기.

추가 대상: BST 멧돼지/곰 진화 보조피해=그 개체 D_basic×0.50, 주대상은1.0. ELM 번개/폭발과 DMN 집행 진화 주변은 원문 동일 피해 유지. 동일 보스는 한 공격당 한 번, 최대대상 수로 DPS를 곱하지 않는다.

### 4.2 표식·동시 사건

DMN은 사건 시작의 표식 스냅샷에서 소비자별 주대상만 예약. 한 적에 소비자 여럿이면 작은 아군 entity_id 한 소비자만 D_basic×k 추가(k=0.5, RELAY시1.0), 나머지는 기본만. HOUND는 시작 표식 참조 시 자신의 기본 피해×1.25, 소비하지 않는다. 같은 시각 소비→기본 적중으로 재적용 순서, 새 표식은 다음 논리 사건부터 사용, 만료시각에는 만료 우선. 죽은 적 표식/예약은 폐기한다. 기본+기존 표식 소비는 하나의 피해 묶음이지 basic_hit 재발행이 아니다. 공통 POWER를 소비 추가분에 또 곱하지 않는다. 표식 적 우선 AI·전장 밖 자동소비 없음.

05의 새 효과 다음 사건 규칙과 DMN 기본 묶음의 해석은 Sam 검토 전이다. 수용 불가하면 05/10/12 공동 수정안으로 올리고 몰래 직업별 예외를 구현하지 않는다.

NEC는 적 정상 사망당 토큰1, 같은 combat_id+entity_id 처리1회. RAISE 전 토큰0, token_cap3, 비용기본3/THRIFT후2, 임시기본3/LEGION후최대5. 같은 시각 사망은 작은 적ID 순서로 골드→토큰→가능 시 소비/생성, 새 임시군 공격은 다음 논리 사건 이후. 상한으로 생성불가 시 소비 안 하고 초과 토큰 폐기, 생성부채 없음. 종료 청소/아군 소멸/보스 승리 잠금은 새 소생 근거가 아니다. 단일 보스 생존 중 토큰0·임시0, 일반전에서 반입0. 보스 재시도 누적으로 증식/시너지 계수 증가 없음.

### 4.3 공격 주기 필드 정정

정본 용어: windup_s=준비, cooldown_s=발사 후 다음 준비까지, interval_s=무중단·정지 시 최소 발사 간격=windup_s+cooldown_s. 첫 공격은 초기 cooldown0에서 준비 후 가능. 이동·취소·비행은 실제 적중 간격과 별개다.

07의 CD/interval 구분과 10의 분리값 유지. 11 §3의 'interval_s는 준비 이후 쿨다운' 문구는 06/07과 충돌하므로 11에 적힌 1/1.2/0.8/1.5/2초는 cooldown_s로 해석하고, 준비0.2초를 더한 interval을 후속에 사용한다. 예: 해골1.2초, 궁수 BASE1.0초/SENTINEL0.8초. 08/09의 공격 원천 null은 여전히 null이며 이 카드가 임의로0을 넣지 않는다. 14에서 채우기 전 공격량/클리어 시간을 확정할 수 없다.
