## 1. 결론과 최소 구현 권고

가능: 장애물·아군 피격·물리 밀어내기 없는 작은 2D 전장은 단순한 개체 목록과 순차 사건 처리로 설계 가능하다. 현재 최대 후보인 적48·NEC 아군10만으로 복잡한 공간 탐색 구조나 병렬 전투 시스템을 먼저 만들 이유는 부족하다. 다만 실제 하드웨어/엔진이 없으므로 프레임·메모리·최대 처리량은 미확인이다. 시각 만족과 지휘 편안함은 문서로 입증되지 않았다.

권고: 현재 지정 후보를 한 번 공유하고 아군별 최근접을 선형 검색하는 A안, 직선 이동·고정 생성 슬롯, 단일 논리 사건 처리기, 판정과 분리한 재사용 그림/효과를 우선 비교한다. 전투→상점→무료 보스→통계의 작은 완결 루프에서 성장 전후를 증명한다. ECS(데이터 중심 대규모 개체 구조), 작업 스레드 분산, 경로 탐색, 전용 마스킹 셰이더는 측정 전 필수가 아니다.

범위 제안: 12의 정령 불씨+번개/5항목 비교안은 제작 비용이 낮은 후보다. BLOOM·SPARK·COMMAND_RADIUS·COM_POWER·COM_SUPPLY만 남기면 기존 전체 카탈로그의 보스 필수집합은 그대로 쓸 수 없다. James가 축소 집합·보스 HP/해금 비용을 P1-18에 재작성해야 한다. 첫 직업·MVP 채택은 대표 결정이며 Sam이 확정하지 않는다. 더 작은 비용 비교안은 불씨1종+개화/반경/화력으로 성장 장면을 먼저 평가하되, 추가 군단 기대감은 증명하지 못한다. 5직업/69항목 전량 제작을 최소안으로 보지 않는다.

G1 유지: 골드는 기본 드랍 즉시 전액 자동 지급, 현재 커서 지정 범위 안 적 공격·범위 확대, 성장/시각 만족 우선, 초기 일반전30초 고정·시간 증가 보류, 보스 입장/실패/재도전 비용과 패널티 없음·재도전 HP 초기화, 무한 성장/환생 제외. 수집 반경·회수율·바닥 골드 원장은 없다. 무피격 문맥 유지, 역할 변화형 군단·복잡 보스 강제 없음. 보스30초/HP1000/보상0/선택 해금/엄격 이탈은 선행의 미승인 제안이다.

## 3. 사건·시간·원장의 최소 계약 [Sam 보완 제안]

### 3.1 전투 시각과 지정 자격

논리 시간은 렌더 프레임 번호가 아니다. 동일 시각 입력/예약/공격/만료를 같은 배치로 묶고 05의 입력→스폰·이동→유효 피해 수집→사망·지급→후속 상태→승패 순서를 보존한다. 시간은 비교 가능한 정수 시간 단위 후보(예: 마이크로초)로 표현하고 데이터 반올림 규약을 한 곳에 둔다. 정밀도 자체는 미확정이다. 준비와 쿨다운은12 정정대로 별도 값이며 무중단 발사 최소간격만 둘의 합이다. 11의 interval 숫자를 다시 발사간격으로 읽지 않는다. 부동소수 오차를 없애려고 임의 유예시간을 T에 붙이지 않는다.

A 정확한 예약 사건 시각을 소비하고 연속 이동/탄 도착·범위 교차를 계산하는 안은 [0,T)와 비행 중 순간 이탈을 엄격히 보존하지만 구현/검증 비용이 높다. B 고정 논리 간격(예:60Hz 가정)에 입력/공격 시각을 양자화하면 쉽지만 한 간격 사이 이탈→재진입과 끝 직전 타격을 놓칠 수 있다. 권고는 작은 수량에서 A를 계약 기준으로 두되, 실제 구현 승인 전에 이동 교차 처리와 입력 기록 정밀도를 명세하는 것이다. B를 선택하면 '즉시'가 표본 시점 기준임을 James/Mia와 명시 합의해야 한다. 고정 간격을 썼다는 이유만으로 정확한 이탈/프레임 독립이 자동 보장되지 않는다.

입력은 수신 순번과 논리 적용시각을 기록한다. 동일 기록 입력·시드에서 렌더30/60/144fps의 결과를 비교한다. 실제 장치가 제공하지 않은 중간 커서 경로를 추측해 엄격 이탈을 보장하지 않는다. 한 입력 갱신 사이의 실제 미관측 이동은 한계로 기록한다. 포인터 점프는 새 C의 자격을 즉시 적용하며 화면 보간 원은 피해 자격을 결정하지 않는다. 이동하는 적/탄의 교차 시각 처리와 비교 오차 규약은 G3 전 상세 미정이다.

프레임 지연으로 누적된 논리 사건은 순서대로 처리한다. 렌더 프레임 예산 초과를 이유로 처치/스폰/골드를 버리지 않는다. 긴 정지에서 한꺼번에 진행하기보다 명시 정지/과부하 상태로 전환하는 정책 후보를 James/Mia와 합의한다. 포커스 상실은 정지, 필드 밖 포인터만으로는 정지하지 않는05 구분 유지. 재개할 때 누적 벽시계 시간을 전투에 더하지 않는다. 표시 시간은16의 종료 전 최소0.1/종료 후0.0 제안을 따를 수 있으나 논리 종료를 연장하지 않는다.

### 3.2 사건 필드·단일 갱신·늦은 이벤트

최소 필드 후보: schema_version, run_id, combat_id, event_id, logical_time, phase, sequence, source_entity_id, target_entity_id, attack_id, primary_target_id, event_kind, invalid_reason, amount_raw, amount_display, state_revision. 피해에는 형상/지정 자격 판정 결과와 원천 공격 참조, 지급에는 death_event_id·gold_final·balance_before/after, 구매에는 purchase_id·upgrade_id·old/new_level·cost·balance_before/after를 추가한다. nullable 필드는 사건별 명시한다. 수치 미정 null을0으로 계산하지 않는다. battle_id/monster_id는 별칭이지 두 번째 지급 키가 아니다.

단일 권한 상태에서 피해 수집→대상별 합산→Alive→Dead 한 번→combat_id+entity_id 지급 키 기록과 지갑 갱신을 한 동작으로 수행한다. 죽음·표식·토큰·승리 이벤트는 확정 사실을 알릴 뿐 원장 재처리를 지시하지 않는다. 전투 종료 청소는 death가 아닌 cleanup. 그림/소리·숫자 표시 큐는 손실 허용, 판정/지급 큐는 손실 불허다. 효과 누락을 지급 누락으로 환산하지 않는다.

전환마다 화면 세대와 전투 세대를 갱신한다. 늦은 콜백은 combat_id/세대/현재 상태를 검사해 폐기한다. 풀링으로 그림 객체를 재사용해도 논리 entity_id는 전투 내 재사용하지 않는다. 같은 타격의 visual callback/animation end는 피해를 다시 만들지 않는다. 중복 사망·정산·클리어 재요청은 원장 불변. 종료 시 전투 입력·공격·예약을 먼저 잠그고 T 미만 미처리 합법 사건이 빠지지 않았는지 확인한 다음 결과 스냅샷을 만든다.

이 '한 번' 보장은 실행 중 단일 상태 갱신 요구다. 디스크 쓰기 도중 강제 종료까지 안전하다는 뜻은 아니다. 저장을 채택하면 파일 버전·임시 파일/교체·복구 지점·중복 요청 보존을 별도 설계해야 한다. 세이브/Steam Cloud/오프라인 수입은 현재 약속하지 않는다.

### 3.3 DMN 표식·NEC 생성 충돌의 실제 검토

조건부 수용: 12§4.2의 기존 표식 보너스를 기본 공격의 같은 피해 묶음으로 해석하면05의 '새 효과 추가 피해는 다음 사건 이후'와 양립 가능하다. 단, 논리 사건을 '같은 시각 전체 전투 배치'로 정의해야 한다. 공격 하나마다 새 사건 스냅샷을 열어 같은 시각 새 표식을 소비하면12 의미가 깨진다.

보완 제안 순서: 시각 t 시작에 만료 우선→표식 스냅샷 고정→유효 공격/주대상만 소비 후보로 예약→적별 작은 아군ID 한 소비자 확정→기본+기존 표식 보너스를 한 번의 피해 수집에 포함→HP 합산/사망→생존 적만 소비 제거 후 같은 시각 유효 표식 적용→다음 시각 배치부터 새 표식 사용. HOUND는 시작 스냅샷 참조, 소비자와 경합해도 배율 참조를 유지한다. 반복 basic_hit 발행 없음, 사망 적에 재표식 없음. 동일 아군의 다중 공격 예약 동률은 attack_id 오름차순 제안을 추가한다. 만료와 적용이 겹치면 옛 표식은 만료, 새 적용은 다음 시각부터다.

표식 적용이 피해0에도 허용되는지, 같은 시각 여러 적용의 duration 갱신 규칙은12만으로 충분하지 않다. 권고는 '유효 적중'에서만 적용하고 새 만료시각은 같은 시각 적용 후보의 최대 만료시각 1개로 합치기다. 새로운 스택은 만들지 않는다. 이는 Sam 제안이며 James 규칙 수용 미합의다. 표식 소비 UI에는 mark_generation/consume_event_id를 주어 같은 소비 강조를 한 번만 낸다. 소비 시 HP가 이미0이면 표시 우선순위는 사망이되 피해/지급 결과는 유지한다.

## 7. 구매·입력 차이와 미합의의 명시적 정정

05§3.1의 상자는 누름 시작 사건으로 개봉,16§3의 UI 버튼은 같은 버튼 안에서 놓을 때 확정이다. 이는 대상 종류를 분리하면 기술적으로 공존한다. 12§2.2는 '단일 구매 의사확정'만 정의해 누름/놓음 자체를 확정하지 않았다. 따라서 상자까지 자동으로 놓음 확정으로 덮어쓰지 않는다. 상자는 기본 미채택이며 채택시 두 방식의 사용성 일관성을 James/Mia와 별도 확인한다. 카드 선택→별도 구매는16의 추가 UX 제안이며05의 전투입력을 늘리는 사양이 아니다.

두 입력안 모두 필요한 최소 안전: 화면 세대+pointer_id+button+누름 대상 저장, 같은 대상/세대의 놓음만 UI확정, 버튼 밖 놓음/포커스 상실/모달/화면전환은 누름 취소, 이미 누른 상태로 새 화면 진입하면 놓음을 소비하고 새 누름까지 대기. 더블클릭 별도 콜백과 click을 둘 다 구매로 연결하지 않는다. purchase_id는 한 번의 의사확정에 하나, 재전달도 같은ID. 최신 레벨/잔액/선행/직업/상점상태를 단일 구매 갱신에서 검사하고 성공시 동일 revision의 지갑/레벨/UI를 표시한다. 구매 처리 중 다음전투와 구매가 경합하면 먼저 접수된 합법 명령만 처리하고 상태 변경 뒤 나머지는 거부한다. 임의 네트워크/서버 구매는 현재 필요 없다.

재진입잠금 A를 채택하면 구매 후 '다음 구매는 버튼에서 커서를 뗀 뒤 다시 눌러 주세요' 상태를 보여 주고, focus 상실 때 누름을 취소한다. 자동으로 버튼이 이동/사라졌다고 재진입을 인정하지 않는 포인터 경계 정책이 필요하다. 다음전투/뒤로는 잠그지 않는다. 최대레벨이면 버튼 제거/완료 표시로 종료한다. 이탈/재진입 요건이 마우스 이동을 늘리는 영향은 James/Mia가 판단한다. Sam은 이를 중복차감 방지와 동의어로 승인하지 않는다.
